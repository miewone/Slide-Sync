# 반복 편집과 파일 로딩 최적화

## 변경 범위

| 항목 | 변경 |
| --- | --- |
| 위치 이동 | 변경된 요소 ID만 전달하고 transform만 갱신하는 경로 추가 |
| 파일 읽기 | 덱을 여는 동안 XML 원문·파싱 결과·관계 정보를 경로별로 재사용 |
| 방향키 실행 취소 | 연속 이동에서 슬라이드별 최초 스냅샷만 생성 |
| 요소·텍스트 조회 | 요소 ID와 미리보기 mover를 Map으로 찾고 텍스트 맞춤 자격을 캐시 |
| 미디어 | 정적 미리보기에서 오디오·비디오 디코딩을 생략하고 인스턴스별 Blob URL 수명 관리 |

새 외부 라이브러리는 추가하지 않았습니다. 원본 PPTX 내용, 편집 적용 범위, 실행 취소 단위와 입력 제한을 유지합니다.

## 구조

### 파일 읽기

`PackageReader`는 `loadDeck` 실행 범위에만 존재합니다. 같은 경로의 동시 요청은 같은 Promise를 공유하며, 원본 문자열을 XML 파싱과 `originalXml`에 재사용합니다. 공통 레이아웃·마스터 관계를 슬라이드마다 다시 압축 해제하지 않습니다. 다른 파일을 열면 별도의 캐시를 만듭니다.

편집기와 외부 렌더러는 여전히 별도의 ZIP/객체 모델을 사용합니다. 이번 변경은 두 모델을 강제로 합치지 않고 편집기 내부의 중복 읽기를 제거합니다.

### 이동과 텍스트 동기화

`syncPreviewPositions(root, slide, {positionOnly:true, ids})`는 지정된 요소의 좌표 변환만 갱신합니다. 순수 이동·정렬은 이 경로를 사용하고, 텍스트 높이 조정·실행 취소·늦게 생성된 iframe의 로드 완료는 기존 전체 동기화를 사용합니다.

미리보기 root/layer와 descriptor 배열별 Map은 WeakMap에 연결합니다. 실행 취소가 descriptor 배열을 교체하면 새 인덱스를 사용하고, 전체 동기화 시 mover 인덱스를 다시 구성합니다. 서로 다른 슬라이드와 iframe의 같은 요소 ID는 섞이지 않습니다.

텍스트 맞춤 후보의 자격은 descriptor 배열 단위로 캐시합니다. 선택 여부는 Set으로 검사하고, 실제 측정·수정에는 최신 `bodyPr`를 다시 읽습니다. 향후 텍스트 내용·요소 타입을 바꾸는 기능을 추가하면 해당 descriptor 캐시도 무효화해야 합니다.

### 연속 방향키 이동

`commitPositions`와 `moveSelected`는 옵션의 `snapshots` Map을 통해 이전 스냅샷을 재사용합니다. 반환 배열의 `changes`에는 이번 호출에서 실제로 변경한 요소 ID를 별도로 담습니다. 따라서 스냅샷 생성은 생략해도 미리보기 갱신은 매번 수행합니다.

키를 놓거나 선택·적용 범위를 바꾸거나 다른 편집을 시작하면 연속 작업이 끝납니다. 실패한 이동도 연속 기록을 종료합니다. 모든 이동 계획을 먼저 검증하므로 무효한 좌표/ID가 포함된 batch는 슬라이드와 보관된 스냅샷을 수정하지 않습니다.

### 정적 미디어 미리보기

앱은 렌더러에 `staticPreview:true`를 전달합니다. 이미지·포스터는 계속 읽되, 재생하지 않는 오디오·비디오의 압축 해제와 Blob URL 생성을 생략합니다. 원본 ZIP의 미디어 바이트는 유지합니다.

외부 렌더러를 일반 모드로 쓰는 경우에는 `PreviewMediaResources`가 인스턴스별 URL을 소유합니다. 파일 교체·실패·destroy에서 URL을 해제하고, 이미 해제된 작업의 늦은 비동기 결과가 새 URL을 만들지 못하도록 합니다. 전역 URL 함수를 가로채지 않아 다운로드나 다른 인스턴스의 URL을 해제하지 않습니다.

## 검증 결과

- `npm test`: 새 파일 읽기·위치/텍스트 캐시·미디어 수명주기 테스트를 포함해 통과.
- `npm run build`: 배포 빌드 통과.
- `npm run test:browser`: 개발 서버, 배포 빌드, 하위 경로 배포의 기존 기능 회귀 검증 통과.

| 검증 | 확인 결과 |
| --- | --- |
| 공통 레이아웃을 쓰는 실제 4장 PPTX | 편집기에서 요청한 각 ZIP 파트의 문자열 읽기 1회 |
| 3장에 대해 방향키 30회 연속 이동 | 슬라이드 XML 스냅샷 직렬화 총 3회 |
| 같은 순수 이동 | 텍스트 스타일 직렬화·자격 XML 재탐색 0회 |
| 키 해제·좌표 한계 실패 이후 | 실행 취소 기록이 분리되고 원래 좌표로 복원 |
| 화면 밖 텍스트 맞춤·늦은 iframe·실행 취소 | 최신 높이·서식·좌표 복원 |
| WAV와 PNG 포스터가 든 파일 3회 열기 | 미리보기 WAV 디코딩 0회, 포스터 표시 정상 |
| 미디어 포함 파일 내보내기 | WAV·PNG 바이트 보존 |
| 일반 미디어 모드 | 반복 로딩·동시 인스턴스·초기화/디코딩 실패·dispose 경쟁 상태에서 URL 정리 |

미디어 브라우저 검증은 유효한 silent WAV와 PNG를 사용합니다. 모든 코덱의 실제 재생을 검증한 것은 아닙니다. 기존 미리보기는 정적 표시를 목적으로 합니다.

추가 검증 모듈은 `core-performance-checks.mjs`, `preview-fit-checks.mjs`, `repeated-edit-checks.mjs`, `media-checks.mjs`이며 메인 브라우저 runner에 연결했습니다. 기존 30·60·120장 합성 덱 검증도 유지합니다.

## 검토와 한계

- 성능은 먼저 구조적 호출 횟수로 확인했습니다. 기존 대형 덱의 드래그 측정은 확정 전 RAF 지연을 측정하므로, 이번 키 반복 확정 비용과 동일한 지표가 아닙니다.
- 좌표 한계의 실행 취소는 원래 좌표로 검증합니다. 큰 좌표를 CSS 문자열로 읽으면 브라우저 직렬화 정밀도 때문에 소수점 반올림 차이가 생길 수 있습니다.
- 원본 XML과 전체 미리보기 동기화 경로를 유지해 텍스트 맞춤·실행 취소 호환성을 보호합니다.
- vendor 내부의 미디어 수명주기를 제한적으로 수정했으므로 렌더러를 업데이트할 때 미디어 회귀 검증을 다시 실행해야 합니다.
- 전체 캐시 생성, 이중 ZIP 로딩, 방문한 iframe의 유지 정책은 남아 있습니다.
