# XML 로딩 호환성

2026-09-15 기준으로 파일 읽기, 미리보기 초기화, 내보내기에서 재현한 문제를 보완했습니다.

## 처리하는 경우

| 문제 | 처리 및 검증 |
| --- | --- |
| XML 문자열 앞의 실제 BOM 또는 `ï»¿` | 마크업 바로 앞의 표식만 정규화. BOM을 거부하는 파서 환경도 모사해 검증 |
| UTF-16 XML을 UTF-8로 읽어 문자 손상 | 바이트의 BOM·초기 패턴·XML 선언으로 UTF-8, UTF-16 LE/BE를 구분. 명시된 다른 인코딩은 브라우저 `TextDecoder` 지원 범위에서 처리 |
| 잘못된 바이트를 대체 문자로 조용히 변환 | 엄격한 디코딩으로 거부하고 내부 경로·인코딩 표시 |
| BOM과 XML 인코딩 선언의 충돌 | 임의 추측 없이 충돌 내용 표시 |
| 수정하지 않은 XML을 다시 쓰면서 원본 인코딩 변경 | 원본 바이트 보관 후 내보내기에 재사용 |
| UTF-16 문서 편집 후 바이트와 선언 불일치 | 편집한 XML의 선언을 실제 출력인 UTF-8에 맞춤. 슬라이드·안내선 편집 후 재가져오기와 실행 취소 검증 |
| 사용자 네임스페이스의 `parsererror` 요소 오인 | 브라우저 파싱 오류 네임스페이스와 구분 |
| 기본 텍스트 스타일 없음 | 빈 기본값으로 미리보기 초기화 |
| 마스터 초기화가 끝나기 전에 로딩 완료 | 마스터와 마스터 노드 초기화를 기다림 |
| 렌더러 초기화 중 오류가 누락되거나 비동기 예외로 남음 | 호출자에게 실패 전달해 기존 간이 미리보기 처리가 실행되도록 함. 실패 시 미디어 URL 해제 검증 |
| 콘텐츠 유형의 Override 요소가 하나뿐임 | 단일 요소도 목록으로 처리 |

편집기, 안내선, 미리보기 엔진의 XML 바이트 읽기는 `XmlPartCodec`을 공유합니다. `PackageReader`는 같은 부분을 반복해서 압축 해제하지 않도록 바이트·문자열·문서를 캐시합니다. 외부 라이브러리는 추가하지 않았습니다.

## 보존과 제한

- 원본 ZIP의 XML·관계·미디어 바이트는 편집하지 않은 경우 유지합니다. ZIP 컨테이너 자체가 바이트 단위로 같다는 의미는 아닙니다.
- 문서 내용의 잘못된 태그, 정의되지 않은 엔터티, 제어 문자를 임의 삭제하거나 복구하지 않습니다. 기존 DTD/엔터티 거부 정책도 유지합니다.
- UTF-32 및 브라우저에서 지원하지 않는 인코딩은 지원 범위 밖입니다.
- 파일을 정상적으로 읽는 것과 PowerPoint의 모든 시각적 효과를 재현하는 것은 별도입니다. upstream에 보고된 EMF/WMF 이미지 등의 미리보기 제한은 이 변경에서 해결한 것으로 간주하지 않습니다.

## 근거와 회귀 검사

- [JSZip 인코딩 제한](https://github.com/Stuk/jszip/blob/main/documentation/limitations.md): 문자열 읽기는 UTF-8을 사용하므로 다른 인코딩은 바이트로 읽어 디코딩해야 합니다.
- [XML 1.0 인코딩 및 자동 감지](https://www.w3.org/TR/xml/): BOM과 선언, UTF-8·UTF-16 처리의 기준입니다.
- [XML 네임스페이스](https://www.w3.org/TR/REC-xml-names/): 같은 로컬 이름이어도 네임스페이스가 다르면 별개 이름입니다.
- [렌더러 upstream 이슈](https://github.com/501351981/pptx-preview/issues): 알려진 시각적 호환성 제한의 추적 위치입니다.

`tests/xml-part-codec.test.js`, `tests/preview-media.test.js`, `scripts/xml-error-checks.mjs`, `scripts/xml-compatibility-checks.mjs`가 BOM, 인코딩, 실패 전파, 다국어 렌더링, 원본 보존, 이동·안내선 편집·실행 취소를 검증합니다.
