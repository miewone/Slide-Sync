# 공통 작업 로그

한글/영어 선택 왼쪽의 작업 로그 아이콘으로 기록을 확인합니다. 새 로그가 추가되면 원형 숫자 배지가 갱신되고 짧은 강조 애니메이션이 실행됩니다. 동작 줄이기 설정에서는 애니메이션을 사용하지 않습니다.

- 숫자는 로그를 비운 뒤 누적된 전체 개수입니다. 열어 보는 것만으로 초기화되지 않습니다.
- 창에는 최근 200개를 최신 순서로 표시합니다. 1,000개부터 배지는 `999+`, 창 제목에는 실제 전체 개수를 표시합니다.
- 시간·결과 구분·작업 내용·파일명을 표시합니다. 작업 안내는 한글/영어 전환에 맞춰 표시하며, 오류 원문과 파일명은 기록 당시 값을 보존합니다.
- 파일 열기, 원본과 같은 웹폰트 사용, 글꼴 확인·적용·실패, 이동·정렬·서식·맞춤·삭제·안내선 변경, 실행 취소·다시 실행, 다운로드 준비를 기록합니다.
- 렌더링 진행률·마우스 이동·단순 선택은 기록하지 않습니다. 누르고 있는 방향키의 연속 이동은 하나의 편집 기록으로 묶습니다.
- 로그 창은 작업 중에도 열 수 있습니다. 로그에서 방향키 등을 눌러도 슬라이드를 편집하지 않습니다.
- 현재 탭의 메모리에만 보관합니다. 로그 비우기 또는 페이지 새로고침으로 초기화하며, 파일을 바꿔 열어도 같은 탭에서는 유지합니다.

## 모듈 사용

`src/services/ActivityLog.js`가 UI와 독립적인 공통 모듈입니다. `App`에서 인스턴스를 하나 만들고 편집기 런타임에 주입합니다. React 기능에서는 `useEditor()`로 같은 인스턴스를 받습니다. 각 기능에서 별도의 인스턴스를 만들지 않습니다.

```js
const {activityLog} = useEditor();

activityLog.record('activity.fontApplied', {
  font: 'Nanum Gothic',
  target: '나눔고딕',
  slides: 4,
}, {level: 'success', fileName: '제안서.pptx'});

// 이미 작성된 사용자 안내 문구를 남길 때
activityLog.write('작업을 완료했습니다.', {level: 'success'});
```

서비스·유틸리티에서도 같은 인스턴스를 생성자나 함수 매개변수로 전달받아 사용합니다. `record(key, params, options)`는 번역 키와 매개변수를, `write(message, options)`는 완성된 문구를 받습니다. 결과 구분은 `info`, `success`, `warning`, `error`입니다.

`subscribe()`와 `getSnapshot()`으로 변경을 구독하고 `clear()`로 비웁니다. 메시지 매개변수는 기록 시점에 복사한 문자열·숫자·불리언만 보관합니다. XML·DOM·응답 객체 같은 가변 객체는 보관하지 않으며 문자열 크기와 항목 수를 제한합니다. 콘솔·네트워크 요청·인증 정보는 자동 수집하지 않습니다.

화면의 상태 문구가 다시 계산되거나 언어가 바뀌는 것만으로 중복 로그가 생기지 않도록, 실제 작업 경계에서 명시적으로 기록합니다. 성공은 해당 작업이 적용된 후, 실패는 사용자에게 보고되는 시점에 기록합니다.

검증: `node tests/activity-log.test.js`, `npm run test:browser -- --check-activity-log`.
