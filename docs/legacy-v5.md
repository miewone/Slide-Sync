# Slide Sync

A browser-only PPTX utility. Pick all slides or a subset, click a point in any preview, select the frontmost slide-level element at that point in each target slide, and move those elements to one absolute X/Y position. A relative movement mode, drag-to-commit, undo and PPTX download are also available.

Ctrl, Shift or Cmd + click adds or removes the corresponding element on every target slide. Dragging an already-selected member retains the whole selection. Multiple elements move as a set with their relative spacing preserved; absolute mode places each slide's selection bounds at the requested position. Selections retain their IDs when slide scope changes. Shift during a drag constrains movement to the dominant axis, preserving the other coordinate independently on each slide, and can be pressed or released mid-gesture.

With preview focus, arrow keys move the selection by 0.1 cm, Shift + arrows by 1 cm, and Ctrl/Cmd + arrows by 0.01 cm. A held arrow key creates one undo gesture. Ctrl/Cmd + A selects all editable slide-level elements; Ctrl/Cmd + Z undoes the last change; Escape cancels a drag or clears selection. Input fields retain their native keyboard behavior. Ctrl + drag moves the selection; it does not duplicate objects.

Alignment controls align left/center/right and top/middle/bottom within each slide's selection or against the slide itself. Equal horizontal/vertical spacing requires at least three selected elements per slide and preserves the two outside elements while equalizing edge-to-edge gaps. Layout uses rotated visual bounds, preserves the original rotations, and is a single undoable batch across checked slides. All selected text boxes participate in selected-only text fitting.

While dragging, each selected slide displays a destination outline at its own component size and rotation. The source preview shows live X/Y coordinates and width/height in centimeters. Pointer updates are batched with `requestAnimationFrame`; they change only the overlay until release commits one edit. Escape, pointer cancellation and lost capture discard the draft.

The Guides panel loads existing presentation-wide guides and the master/layout guides that apply to each slide. Add horizontal or vertical common guides, enter a position measured from the top/left in centimeters, or enable guide dragging to move them across all previews. Common guides can be deleted, exported to PPTX and undone. Master/layout guides are displayed read-only. Visibility and snapping are view preferences; they do not delete guides. Guide drags use the same draft/commit and cancellation behavior as element drags.

Element drags snap the visual selection edges or center to guides in the active preview within six CSS pixels. Shift keeps the movement axis locked; holding Alt temporarily disables snapping. Numeric positions, keyboard nudges and alignment actions retain their exact requested coordinates. Guide overlays update in place without re-rendering slides or reloading preview frames.

The text-box fit action works on all text boxes in checked slides or just the selected boxes. It preserves width, position and declared font sizes, grows or shrinks height to measured wrapped content, and writes DrawingML `a:spAutoFit` with wrapping. Measurement clones the cached text into an isolated offscreen layout, waits for fonts, and batches layout reads. Preview geometry and text styles update in place, and one undo restores the complete batch. Titles and plain unfilled text rectangles from generators that omit `txBox` are supported. Text inside groups, vertical/rotated text bodies, multiple columns and unavailable rendered text are skipped. Font substitution and browser/PowerPoint layout differences can affect the final native height.

The original PPTX is never uploaded. JSZip reads the package in memory. `dist/core.js` follows presentation relationship order, reads DrawingML transforms, resolves layout/master placeholder geometry, and selects elements in reverse drawing order. Groups are selected and moved as a unit. Hit testing uses the rotated element rectangle; group testing uses its child elements. Clicks are projected from the preview to the presentation's EMU coordinates. 1 cm = 360,000 EMU.

Selection and scope changes preserve existing iframe documents. Movement and undo update element translation wrappers in the cached preview and its script-disabled, same-origin frame. Original rotation, sizing and z-order stay inside the wrapper. Whole-deck parsing/rendering occurs only when a file is opened; ZIP encoding occurs only during download. Small pointer movements are treated as clicks, and no-op moves do not add history.

The preview uses the published `pptx-preview` package, with an explicit mapping from presentation slide paths to the renderer's slide ordering. Preview frames have no script permissions. Package rendering is isolated from the editing model. If the renderer cannot display a slide, an explicitly labelled outline preview is shown.

`dist/preview-theme.js` adapts inherited artwork rendering so master/layout decorations without `userDrawn` are included. Placeholder samples and hidden shapes are excluded, and slide/layout `showMasterSp` settings control master artwork. Inherited layers retain native order and scale and remain separate from editable slide shapes. No package XML is changed by this adapter. It uses the bundled renderer's internal layer methods; changes to that dependency should rerun the regression fixture.

Theme regression: serve the repository root and open `/tests/preview-theme.html`. The test reproduces the original missing-master-shape behavior and verifies artwork, colors, placeholder/hidden-shape exclusion, master visibility, duplicate IDs across parts, movement and undo using the actual bundled renderer. This fixture passes in headless Chrome; native PowerPoint visual comparison has not been performed.

Exports update the affected slide XML and edited guide metadata, retaining other package parts. Unmodified slide XML is retained byte-for-byte. Undo restores the pre-edit XML. Slides with inherited placeholders receive local transforms when moved. Background and master-level objects are not edited. This is not a full PowerPoint rendering engine: font substitution, custom geometry, effects, SmartArt and unsupported media can differ. Unsupported elements without resolved geometry are excluded. Limits: 50 MiB compressed input, 300 MiB declared decompressed input, 120 slides, 25 undo operations.

Guide import supports the legacy `p:guideLst` in view properties and modern `p15:sldGuideLst` extensions in the presentation, master and layout. Modern presentation guides take precedence over the legacy compatibility list. Positions use PowerPoint master units (1/576 inch, or 1587.5 EMU) from the top-left, as specified in [MS-PPTX](https://learn.microsoft.com/en-us/openspecs/office_standards/ms-pptx/). Common-guide edits synchronize existing modern and legacy lists, preserving native guide metadata and untouched inherited parts. Missing view properties are created with the required relationship and content type. Undo followed by export restores original metadata, including removing parts created by a previous export. RGB guide colors are displayed; theme-based colors use a scope-specific fallback while their native color XML is retained.

Static application: deploy `dist/`. No build or remote services are required. Serve it over HTTP, not `file://`, because it uses ES modules and a local sample file. Third-party notices are in `dist/vendor/NOTICE.txt`.
