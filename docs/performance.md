# 미리보기 최적화 측정

## 적용한 변경

- 슬라이드·레이아웃·마스터 XML의 실제 DrawingML 차트 참조를 검사하고, 차트가 있는 덱에만 ECharts를 로드합니다. ZIP에 사용하지 않는 차트 파일만 있는 경우에는 로드하지 않습니다.
- 차트 없는 파일을 먼저 연 뒤 차트 파일을 열어도 동작하도록 어댑터가 호출 시점에 라이브러리를 참조합니다. 기존 라이브러리와 버전을 유지했으며 외부 패키지를 추가하지 않았습니다.
- 화면 근처의 슬라이드를 먼저 렌더링하고 준비된 내용을 즉시 보여 줍니다. 화면 밖 슬라이드는 순차적으로 캐시하며 iframe은 접근할 때 생성합니다.
- 드래그는 전체 선택의 이동 계획을 유지하면서 화면 근처의 변경 대상만 DOM 갱신합니다. 안내선 맞춤 강조는 기준 슬라이드만 갱신합니다.
- 슬라이드 경로를 한 번 Map으로 연결하며, 내용이 같은 UI 행·선택 요약은 기존 참조를 유지합니다.

ECharts 파일은 현재 **1,030,855바이트**, gzip 계산 시 **335,021바이트**입니다. 차트 없는 파일에서는 해당 스크립트 요청 자체가 발생하지 않습니다. 실제 전송량은 서버 압축·캐시 설정에 따라 다릅니다.

## 비교 결과

변경 전 배포 빌드와 변경 후 배포 빌드에 동일한 합성 PPTX를 적용했습니다. 아래 값은 각각 한 번씩 측정한 결과이며 성능 보장값이나 여러 실행의 평균은 아닙니다.

| 슬라이드 수 | 첫 미리보기 내용 로드 (전 → 후) | 초기 iframe (전 → 후) | JS 힙 MiB (전 → 후) | 드래그 갱신 p95 ms (전 → 후) |
| --- | --- | --- | --- | --- |
| 30 | 507 → 161 ms | 30 → 8 | 11.0 → 5.7 | 5.4 → 2.3 |
| 60 | 828 → 216 ms | 60 → 8 | 17.9 → 6.3 | 17.1 → 3.5 |
| 120 | 1,715 → 300 ms | 120 → 8 | 31.8 → 8.7 | 16.8 → 4.9 |

전체 캐시가 준비되어 편집이 활성화될 때까지의 시간은 각각 **545 → 438ms**, **864 → 867ms**, **1,625 → 1,471ms**였습니다. 첫 미리보기 표시 개선이 전체 덱 처리 시간 개선과 같지는 않습니다. 편집·텍스트 측정을 위해 모든 슬라이드의 캐시를 계속 준비합니다.

120장 기준 관측된 DOM 노드 수는 **85,458 → 73,921개**였습니다. JS 힙 수치는 DOM·그래픽·프로세스 전체 메모리가 아니며, iframe 컨텍스트와 ECharts 로딩을 줄인 효과가 함께 포함됩니다.

## 측정 조건과 정의

- 브라우저: 설치된 headless Chrome, 1440 × 1000, deviceScaleFactor 1, GPU 비활성화.
- 서버: 로컬 Vite preview. CPU·네트워크 제한을 걸지 않았습니다.
- 입력: 포함된 예제의 첫 슬라이드를 30·60·120장으로 복제한 차트 없는 덱. 실제 고객 파일이나 이미지·효과가 많은 덱을 대표하지 않습니다.
- 픽스처 생성을 위해 JSZip과 샘플 파일은 타이머 시작 전에 로드했습니다. 실제 사용 시 ZIP 라이브러리의 최초 다운로드 시간은 추가될 수 있습니다.
- 페이지 간 메모리 비교를 위해 Chrome BackForwardCache를 비활성화하고 힙 측정 전에 GC를 요청했습니다.
- 첫 미리보기: 파일 입력 이벤트부터 첫 iframe의 `load` 이벤트에서 편집 요소가 확인될 때까지. 브라우저의 실제 화면 페인트 지표는 아닙니다.
- 편집 활성화: 다운로드 버튼이 활성화되는 시점. 100ms 간격의 자동화 확인 오차가 포함됩니다. 기존 빌드는 iframe 로드가 끝나기 전에 활성화될 수 있습니다.
- JS 힙: DevTools `Runtime.getHeapUsage().usedSize`. DOM 카운터는 `Memory.getDOMCounters`로 수집했습니다.
- 드래그 p95: 전체 요소를 선택한 상태에서 실제 포인터 이동 10회 이상을 보내고, 이벤트 수신부터 편집 런타임의 RAF 갱신 다음 콜백까지 걸린 시간의 95백분위입니다. 화면 출력 지연이나 입력 장치 지연 전체는 포함하지 않습니다.
- 초기 8개 iframe은 이 화면 크기와 300px 여유 영역에서의 결과입니다. 고정 개수 제한이 아니며, 스크롤한 뒤 이미 생성된 iframe은 유지됩니다.

## 검증과 재실행

```bash
npm test
npm run build
npm run test:browser
```

브라우저 검증은 기존 개발·배포·하위 경로 테스트에 다음 항목을 추가합니다.

- 차트 없는 파일에서는 ECharts 요청 없음.
- 같은 페이지에서 나중에 여는 차트, 레이아웃 차트, 마스터 차트의 SVG 생성.
- 그룹 내부 차트 참조도 의존성 감지 대상에 포함. 단, 기존 렌더러가 그룹 내부 차트 자체를 그리지 못하는 제한은 유지됩니다.
- 30·60·120장 덱의 초기 iframe 개수와 점진적 표시.
- 아직 iframe이 없는 마지막 슬라이드까지 이동·텍스트 높이 맞춤 적용.
- 마지막 슬라이드로 스크롤하면 최신 위치와 높이를 표시하고 실행 취소 때 같은 iframe 유지.

최신 결과는 `artifacts/optimization-metrics.json`에 저장됩니다. 변경 전후를 다시 비교하려면 **변경 전 빌드**를 먼저 `artifacts/baseline/`에 보관한 뒤 변경 후 빌드를 생성하고 다음을 실행합니다.

```bash
npm run test:browser -- --benchmark-baseline
```

비교 모드에는 추가 로컬 포트 4190이 필요합니다. 기존 빌드 보관본은 생성 산출물이므로 저장소 소스에는 포함하지 않습니다.

## 검토

- 성능: 첫 표시와 초기 iframe·JS 힙 사용량, 드래그 갱신 지연이 합성 테스트에서 개선됐습니다. 전체 캐시 생성 비용과 이중 PPTX 파싱은 남아 있습니다.
- 보안: iframe 스크립트 금지, 렌더 결과 정리, 기존 입력 제한과 로컬 처리 방식을 유지합니다.
- 확장성: 화면 관찰, 차트 의존성 감지, 표시 행 재사용을 별도 모듈로 분리했습니다. 새 차트 형식이나 렌더러를 도입하면 의존성 감지와 브라우저 검증을 함께 확장해야 합니다.
