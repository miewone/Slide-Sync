# 편집기 구조와 확장 기준

## 모듈별 책임

```text
React UI → 안정적인 commands → 편집 런타임 → PPTX 도메인 모듈
   ↑                            ↓
필드별 구독 ← EditorStore ← 화면 상태 요약
                                ↓
                     캐시된 미리보기 / 안내선 DOM
                                ↓
                     PreviewResources 지연 로딩
```

`App`은 편집기 인스턴스와 수명주기를 소유합니다. 명령 객체의 참조는 일정하게 유지되며 현재 런타임으로 호출을 전달합니다. 상태 저장소와 도메인 상태는 인스턴스마다 독립적입니다. 라이브러리 로딩만 공유합니다.

`EditorStore`에는 이름, 상태 메시지, 목록, 선택 요약 같은 표시 데이터만 둡니다. 큰 ZIP/XML 객체, DOM, 미리보기 캐시는 React 상태에 넣지 않습니다. `useEditorValue(key)`는 필드 참조가 바뀔 때만 해당 구독 컴포넌트를 갱신합니다. 슬라이드 행은 `memo`와 원시 타입 props를 사용합니다. `shareRows`는 표시 내용이 같은 행과 배열의 참조를 재사용하며, `updateSelection`은 내용이 같은 요약의 알림을 생략합니다.

`PreviewResources`는 라이브러리를 불러오는 역할만 담당합니다. ZIP 파서는 파일 해석 시, 도형 렌더러는 미리보기 생성 시 로드되며, ECharts는 슬라이드·레이아웃·마스터 XML에 차트 참조가 있을 때만 로드됩니다. 차트 어댑터는 실제 호출 시 전역 라이브러리를 참조해 차트 없는 파일 다음에 차트 파일을 여는 흐름을 지원합니다. 같은 요청은 Promise를 공유하고 실패한 요청은 재시도할 수 있습니다. ES 모듈 렌더러는 Vite가 별도 청크로 빌드합니다. 기존 UMD 라이브러리는 로컬 정적 자산으로 유지하여 의존성 버전 변경을 최소화했습니다.

## DOM 소유권

| 영역 | 소유자 | 변경 방식 |
| --- | --- | --- |
| 헤더, 슬라이드 목록, 상태, 선택 결과 | React | 상태 구독과 컴포넌트 렌더링 |
| `#stage` 요소 자체 | React | 안정적인 호스트 유지 |
| `#stage`의 자식과 iframe 내부 | 편집 런타임 | 파일 열기 시 생성, 편집 시 위치만 갱신 |
| 이동·정렬·안내선·텍스트 도구의 입력값과 활성 상태 | 편집 런타임 | 네이티브 DOM 속성과 이벤트 |
| 도구 패널의 정적 구조 | React | 공용 컴포넌트 조합 |

입력은 의도적으로 uncontrolled 방식입니다. 예를 들어 드래그 중 X/Y 초안을 즉시 갱신할 때 React의 비동기 상태 갱신이 초안을 덮어쓰지 않습니다. 해당 패널에 새로 `value`, `checked`, 동적인 `disabled` props를 추가하려면 먼저 그 필드의 소유권을 React로 완전히 옮겨야 합니다. React와 런타임이 같은 속성을 동시에 관리하지 않도록 합니다.

마스터·레이아웃 장식은 편집 가능한 슬라이드 도형과 다른 레이어에 둡니다. 서로 같은 도형 ID를 사용해도 이동 캐시가 테마 도형을 옮기지 않습니다.

## 공용 컴포넌트 사용

새 버튼·입력은 `components/ui.jsx`의 `Button`, `SelectField`, `Checkbox`, `NumberField`를 사용합니다. 관련 도구들은 `InspectorSection`으로 묶습니다. 정렬 명령처럼 반복되는 UI는 행동/라벨 데이터로 정의합니다.

새 편집 동작은 `core`, `layout`, `guides`, `text-fit`과 같은 도메인 모듈에 구현하고 런타임에서 호출합니다. UI 컴포넌트에 PPTX XML 수정이나 ZIP 처리를 넣지 않습니다. 새로운 외부 패키지는 프로젝트 승인 지침을 따릅니다.

## 성능·보안·확장성 검토

- 성능: 큰 라이브러리를 초기 로딩에서 제외하고, 드래그·이동 중 전체 덱 렌더링이나 ZIP 재생성을 피합니다. 브라우저 동작·요청 횟수와 30·60·120장 합성 덱을 검증했으며, [성능 측정](performance.md)에 조건을 기록했습니다. 실제 사용자 파일 전체를 대표하는 벤치마크는 아닙니다.
- 보안: PPTX 업로드 경로를 추가하지 않았습니다. 배포 빌드에 CSP를 적용하고 미리보기 iframe의 스크립트 금지·HTML 정리·입력 제한을 유지합니다. 개발 CSP는 Vite HMR과 별도로 취급합니다.
- 확장성: 표시 데이터와 도메인·미리보기 엔진을 분리했습니다. 네이티브 입력/미리보기 연동은 기존 DOM 기반 로직을 유지하므로, 향후 UI를 더 선언적으로 바꿀 때 이 경계부터 순차적으로 교체하면 됩니다.
- 의존성: 기존 렌더러 내부 API에 의존하는 테마 어댑터는 렌더러 버전 변경 시 반드시 브라우저 테마 테스트로 확인해야 합니다. 기존 번들 전체의 재설계나 차트별 ECharts 분할은 이번 범위에 포함하지 않았습니다.

## 검증과 리소스 정리

`EventScope`는 전역 이벤트를 누적시키지 않고 편집기 root와 window 이벤트를 해제합니다. 런타임 해제 시 드래그 RAF, ResizeObserver, 오프스크린 호스트, 캐시를 정리합니다. 비동기 파일/렌더러 로딩 이후 활성 상태를 확인해 해제된 화면에 결과를 적용하지 않습니다.

브라우저 테스트는 React 개발 모드와 실제 빌드를 모두 실행하며, iframe 문서 동일성·ZIP 생성 횟수·내보낸 좌표의 재해석을 검증합니다. 루트 경로뿐 아니라 하위 경로용 빌드도 별도로 생성해 확인합니다. 구체적인 실행 명령은 루트 README를 참고하세요.


## 화면 근처 미리보기와 드래그

`PreviewViewport`는 stage를 스크롤 기준으로 사용하고 위아래 300px의 여유 영역까지 관찰합니다. 모든 슬라이드는 먼저 가벼운 카드 껍데기를 갖습니다. 렌더링 큐는 관찰된 슬라이드를 우선 처리하며 캐시가 준비되면 즉시 iframe을 붙입니다. 다른 슬라이드는 순차적으로 준비하고 스크롤로 접근하면 그때 iframe을 생성합니다.

편집기의 `busy` 상태는 전체 캐시가 완성될 때까지 유지됩니다. 그 뒤에는 화면 밖 슬라이드도 동일하게 선택·이동·텍스트 맞춤·내보내기 대상입니다. iframe 생성 전에 변경된 위치와 높이는 캐시에서 직렬화되고, 로드 완료 시 현재 도형 상태를 다시 동기화합니다. iframe을 내보내거나 다시 만들지 않기 때문에 이미 방문한 슬라이드의 문서 동일성은 유지됩니다. 따라서 이 구현은 초기 iframe 생성을 지연하며, 방문한 iframe을 제거하는 메모리 상한형 가상화는 아닙니다.

드래그 중 데이터상의 이동 계획은 전체 선택에 대해 유지합니다. DOM 갱신만 화면 근처의 선택 슬라이드로 제한하며, 안내선 맞춤 강조는 기준 슬라이드로 제한합니다. 스크롤로 들어온 카드는 현재 선택·드래그·안내선 상태를 새로 반영합니다. 전역 안내선 이동은 화면 근처의 모든 슬라이드에 계속 표시됩니다.

덱 교체 시 관찰과 DOM 참조를 초기화하고, 이전 surface에서 늦게 도착한 observer 기록은 버립니다. 렌더러의 슬라이드 경로는 Map으로 한 번 매핑합니다. 차트의 destroy 콜백이 원본 렌더 DOM을 정리하므로, 미리보기 캐시는 안전하게 복제한 DOM을 계속 사용합니다.


## 사각형 범위 선택

`RangeSelection`은 드래그 방향과 무관한 사각형 정규화, 회전된 요소 경계의 완전 포함 판정, 적용 대상별 선택 집합 합성을 담당합니다. 입력 선택 집합을 변경하지 않으며 마스터·레이아웃 장식, 숨김 또는 위치를 해석하지 못한 요소는 선택하지 않습니다. 도메인 연산은 포인터를 놓을 때 한 번 수행합니다.

`BoxSelectionGesture`는 임계 거리, 포인터 캡처, RAF 단위의 초안 좌표, 취소를 담당합니다. 드래그 초안에서는 선택 집합을 변경하지 않습니다. 마지막 포인터 좌표로 확정하므로 예약된 RAF가 아직 실행되지 않았더라도 끝 좌표를 놓치지 않습니다. 좌표는 슬라이드 안으로 제한하며 역방향 드래그도 같은 결과를 냅니다.

기본 라우팅은 빈 영역에서 범위 선택, 요소 위에서 기존 이동입니다. 명시적 ‘영역 선택’ 모드는 요소 위에서도 범위 선택을 시작하도록 합니다. Shift는 영역 선택 시작 시 추가 선택을 의미하고, 기존 요소 이동에서는 계속 방향 고정을 의미합니다. 안내선 편집은 기존 포인터 우선순위를 유지합니다.

사각형은 `PreviewViewport`가 관리하는 화면 근처의 적용 대상과 드래그 원본에만 표시합니다. 드래그 중 전체 요소를 반복 검사하거나 React 표시 상태를 계속 새로 만들지 않으므로, 기존 미리보기 캐시·iframe·ZIP 최적화를 유지합니다. 선택 확정 후에도 화면 밖 슬라이드의 선택 ID는 유지되며 접근 시 표시됩니다.


## 정렬 컨트롤

정렬 패널은 오른쪽 상단에 놓고 가로·세로 방향을 각각 이름 있는 fieldset으로 표시합니다. 동작 ID는 기존 `layoutPlans` / `alignSelected` 경로를 재사용합니다. `layout-options.js`의 공용 정의를 버튼과 완료 메시지가 함께 참조하며, 별도의 정렬 상태나 중복 도메인 로직은 만들지 않습니다.

선택 영역 기준에서는 한 슬라이드에 2개 이상, 슬라이드 기준에서는 1개 이상 선택한 경우에만 활성화합니다. 선택 조건을 만족하는 적용 대상 슬라이드 수를 도움말로 표시합니다. 브라우저 검증은 여섯 방향, 변경하지 않는 축, 선택하지 않은 요소·슬라이드의 보존, 실행 취소와 iframe·ZIP 재사용을 확인합니다.


## 문자열 기반 적용 대상 선택

`SlideSearchIndex`는 파일을 열 때 한 번 생성합니다. 슬라이드 XML의 DrawingML 단락을 읽고, 같은 단락 안의 서식 run과 field 텍스트를 이어 붙입니다. 단락·명시적 줄바꿈은 공백으로 분리하며 NFKC·소문자·연속 공백 정규화 결과만 보관합니다. 제목 표시용 80자 제한이나 미리보기 DOM에 의존하지 않으므로, 화면 밖 슬라이드와 표·그룹 내용도 검색할 수 있습니다.

`SlideSearch`는 React가 관리하는 독립 컴포넌트입니다. 검색어와 일치 인덱스는 `EditorStore.slideSearch`로 전달하고, 목록 행은 일치 여부가 바뀔 때만 다시 그립니다. 입력 중에는 검색 결과만 갱신하고 버튼이나 Enter로 확정할 때 기존 `setChecked`를 호출합니다. 추가는 집합 합집합, 해제는 일치 인덱스 제거로 처리해 관련 없는 체크를 유지합니다. 한글 조합 중 Enter는 적용 명령으로 처리하지 않습니다.

- 성능: 각 입력에서 XML·ZIP을 다시 읽지 않고 정규화된 문자열을 검사합니다. 이동·정렬·텍스트 높이 맞춤은 글자 내용을 바꾸지 않으므로 인덱스를 재생성하지 않습니다.
- 보안: 검색어를 정규식이나 HTML로 해석하지 않습니다. 검색 데이터는 기존 PPTX 처리와 같이 브라우저 안에 유지됩니다.
- 확장성: 추출과 검색을 UI에서 분리했습니다. 추후 글자 내용 편집을 추가하면 해당 슬라이드의 인덱스 무효화도 구현해야 합니다.
- 수명주기: 새 덱을 적용할 때 인덱스를 교체하고 검색어를 초기화합니다. 파일 해석 실패 시 이전 인덱스와 검색 상태를 복원하며, 편집기 해제 시 인덱스를 비웁니다.

브라우저 검증은 개발·배포·하위 경로에서 긴 본문, 서식 run, 표, 그룹, Unicode·특수문자, 빈 검색어, 키보드·조합 입력, 적용 대상 추가·해제와 원본 XML/미리보기 재사용을 확인합니다.


## 요소 검색과 접히는 편집 카테고리

`SearchText`는 슬라이드 검색과 요소 검색이 함께 쓰는 텍스트 추출·정규화 규칙입니다. `SearchSelection`은 두 검색 UI의 조합 입력 처리, Enter/Shift+Enter, 일치 선택·해제를 공유합니다. 기존 슬라이드 검색의 ID와 동작을 유지했습니다.

`ElementSearchIndex`는 파일 로드 때 편집 가능한 슬라이드 최상위 요소의 이름·전체 텍스트를 저장합니다. 그룹은 보이는 자식의 텍스트·이름을 합쳐 그룹 ID 하나로 반환하고, 숨김 요소 및 해석 가능한 좌표가 없는 최상위 요소는 제외합니다. 검색 결과는 `(slide index, element ID)` 쌍이므로 슬라이드 간 같은 ID가 섞이지 않습니다.

검색 대상은 현재 체크한 슬라이드입니다. 런타임은 검색어·인덱스·체크 Set의 참조가 바뀔 때만 일치 목록을 다시 계산하고, 선택만 바뀔 때는 선택된 일치 개수만 갱신합니다. 기존 선택에 집합 단위로 추가·해제하며 체크 범위와 원본 XML, 실행 취소 이력은 변경하지 않습니다. 파일 교체 시 인덱스와 검색어를 교체하고, 실패한 가져오기는 이전 검색 상태로 복원합니다.

`InspectorSection`은 공용 native `details/summary` 경계입니다. 카테고리를 접어도 자식을 조건부로 제거하지 않아 런타임이 참조하는 input/select/button의 DOM과 네이티브 이벤트가 유지됩니다. 기본적으로 검색·정렬·이동을 펼치고 안내선·텍스트 맞춤·선택 결과를 접습니다. 선택 요약과 실행 취소는 카테고리 밖에 둡니다. 같은 페이지에서 파일이나 검색/선택 상태가 바뀌어도 사용자가 조작한 open 상태를 강제로 덮어쓰지 않습니다.

### 검토

- 성능: 검색은 캐시된 문자열을 사용하고 입력·선택 변경으로 PPTX를 재해석하지 않습니다. 카테고리 조작으로 iframe을 생성하거나 ZIP을 압축하지 않습니다.
- 보안: 요소 이름과 검색어를 HTML·정규식으로 실행하지 않고, 편집 가능성 검사를 통과한 객체만 선택합니다.
- 확장성: 검색 UI·텍스트 규칙·대상별 인덱스·접힘 경계를 분리했습니다. 향후 텍스트나 요소 이름 편집을 추가하면 해당 검색 인덱스 무효화가 필요합니다.

브라우저 검증은 개발·배포·하위 경로에서 요소 이름/텍스트, 그룹 선택, 체크 범위와 기억된 선택, IME/키보드, 여섯 카테고리의 독립 토글, 입력 DOM/값 보존, 접은 상태의 실행 취소, 파일 교체·실패 복구와 iframe/ZIP 재사용을 확인합니다.


## 비활성 미리보기 활성화

미리보기 surface의 기본 포인터 입력을 capture 단계에서 확인하고, 체크 해제된 슬라이드라면 기존 `setChecked` 경로로 해당 인덱스만 추가합니다. 활성화 제스처는 요소·범위·안내선 드래그로 전달하지 않아 첫 클릭이 편집까지 실행되지 않습니다. 카드 머리글 체크박스는 surface 밖에 두어 체크 해제 동작을 유지합니다. Enter/Space 활성화도 같은 경로를 사용하며, 처리 중·보조 버튼·비주 포인터는 제외합니다.

선택 기억, 검색 결과의 선택 개수, 목록·카드 체크와 미리보기 강조는 기존 범위 갱신을 재사용합니다. 원본 XML이나 실행 취소 이력을 수정하지 않고 iframe을 재생성하지 않습니다.


## 미리보기 호버와 왼쪽 목록 연결

카드의 pointerenter/pointerleave는 별도의 `hoveredSlide` 표시 상태만 갱신합니다. React 목록 행은 해당 인덱스만 강조하고, `scrollSidebarRow`가 사이드바 내부의 스크롤 컨테이너만 조절해 행을 드러냅니다. 미리보기·페이지 스크롤, 키보드 포커스, 체크 범위와 편집 기준 슬라이드는 변경하지 않습니다. 포인터가 떠나거나 덱을 교체하면 호버 상태를 해제합니다. 터치 접촉은 호버로 취급하지 않습니다.
